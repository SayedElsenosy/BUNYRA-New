# BUNYRA ERP & CRM

منصة SaaS لشركات التطوير العقاري. هذا المستودع هو المصدر المعتمد للمشروع الجديد.

## التقنية

Next.js 16 / React 19 / TypeScript / Neon PostgreSQL / Neon Managed Better Auth.

الاستضافة المقترحة: Netlify Free مع قاعدة Neon الحالية. يدعم المشروع أيضًا خادم Node.js عادي. لم تنشأ خدمة Render وفق رغبة صاحب المشروع.

## المنجز

- لوحة مالك المنصة وإدارة الشركات: إنشاء وتعديل وتفعيل وإيقاف، والبحث والإحصاءات الفعلية.
- دعوات مرتبطة بالبريد، وقبول مرة واحدة، وانتهاء وإلغاء وإعادة إصدار آمن. تخزن تجزئة رمز الدعوة فقط.
- إدارة العضويات والأدوار الأساسية والمخصصة وصلاحيات الشركة والمشروع، ومنع تعطيل آخر مدير نشط والتعديلات بإصدار قديم.
- فصل هوية مالك المنصة عن مستخدمي الشركات وتسجيل وصوله وتعديلاته.
- عزل PostgreSQL RLS يتحقق من المستخدم والعضوية النشطة وحالة الشركة، مع تحقق الصلاحيات في الخادم.
- سجل تدقيق للتغييرات والقيم السابقة واللاحقة، بما فيها العمليات المتزامنة.
- واجهات عربية وإنجليزية واتجاها RTL/LTR والوضعان الفاتح والداكن.
- تهيئة دخول مستقل بالبريد وكلمة المرور عبر Neon Auth، وصفحة تأكيد البريد برمز OTP. لا يعتمد التطبيق على حساب ChatGPT أو ترويساته.

المتطلبات الأصلية: docs/requirements.md. الوحدات اللاحقة من المشروعات والمخزون والمخططات وCRM والحجوزات والعقود والمالية لم تنفذ بعد. الصلاحيات المسبقة لها لا تعني اكتمالها. لا توجد خدمات LLM داخل التطبيق.

## التشغيل محليًا

يتطلب Node.js 22.13 أو أحدث.

1. npm ci
2. توفير متغيرات .env.example في بيئة تشغيل محلية غير متعقبة، باستخدام فرع Neon للتطوير.
3. npm run dev

للبناء: npm run build. للتشغيل بعد البناء: npm start. للفحص: npm run typecheck.

## نشر Netlify

اربط المستودع الخاص SayedElsenosy/BUNYRA-New من لوحة Netlify واختر الخطة Free. ملف netlify.toml يحدد بناء Next.js وينشر .next؛ يهيئ Netlify خادم SSR وAPI تلقائيًا. لا تستخدم نشرًا ثابتًا أو رفع مجلد public وحده لأن التطبيق يتضمن Backend.

أضف المتغيرات التالية عبر إعدادات أسرار Netlify، ولا تضع قيمها في GitHub أو netlify.toml:

- DATABASE_URL: اتصال Neon بقاعدة التشغيل، pooled.
- NEON_AUTH_BASE_URL: عنوان Neon Auth لفرع التشغيل.
- NEON_AUTH_COOKIE_SECRET: قيمة عشوائية قوية، 32 حرفًا أو أكثر.
- PLATFORM_OWNER_EMAIL: بريد مالك المنصة المعتمد.
- ALLOW_OWNER_BOOTSTRAP: true أثناء التهيئة الأولى فقط، ثم false بعد تهيئة المالك.

أضف عنوان الموقع الفعلي إلى Trusted Origins في Neon Auth لفرع التشغيل. لا تستخدم wildcard عامًا.

سجّل حساب المالك بالبريد المعتمد وأكده برمز البريد قبل الدخول. لا توجد كلمة مرور افتراضية. لا ينشأ دور المالك من ترويسة يرسلها المتصفح: هوية Neon الموثقة والبريد المؤكد مطلوبان للتهيئة. حسابات الشركات الأخرى تتطلب دعوة حتى بعد التسجيل.

بعد النشر اختبر /api/health والدخول والخروج واستعادة الجلسة ورفض الطلبات المجهولة أو الترويسات المزورة، ثم إنشاء شركة ودعوة حساب منفصل. لا تضع بيانات تشغيل حساسة قبل إنهاء اختبار المتصفح والأمان والنسخ الاحتياطي.

## قاعدة البيانات والاختبارات

طبقت migrations 001 و002 على قاعدة Neon الجديدة فقط. لا تنفذ migration 001 على قاعدة موجودة. قاعدة التشغيل بدأت بلا شركات أو مستخدمين تجريبيين، وبيانات الاختبار بقيت على dev-foundation.

نجحت 38 حالة للخدمات وقاعدة البيانات في النسخة السابقة من طبقة الأعمال المحفوظة هنا؛ النتائج في docs/identity-test-results.json. لا تعني تلك النتائج اكتمال اختبارات الدخول الجديد أو Netlify. راجع docs/hosting-validation.md لنتائج التحقق الخاصة بهذه النسخة.

لتكرار اختبارات قواعد العمل على فرع مستقل:

1. node scripts/prepare-identity-tests.mjs
2. توفير BUNYRA_TEST_DATABASE_URL لفرع اختبار مستقل وBUNYRA_ALLOW_TEST_FIXTURES=1 عبر أسرار البيئة.
3. node scripts/run-identity-tests.mjs

لا تستخدم قاعدة التشغيل للاختبارات. المجموعة تنشئ سجلات اختبار ولا تحذف بيانات أعمال سابقة.
