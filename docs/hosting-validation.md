# توثيق الانتقال إلى استضافة مستقلة

- المصدر: SayedElsenosy/BUNYRA-New.
- إطار التشغيل: Next.js 16.3.4 / React 19.2.6.
- حزمة الهوية المثبتة: @neondatabase/auth 0.6.0-beta، والإصدارات الفعلية مثبتة في package-lock.json.
- أزيل اعتماد تشغيل التطبيق على Cloudflare/Sites وترويسات هوية ChatGPT من هذه النسخة.
- أضيفت واجهات إنشاء الحساب والدخول وتأكيد البريد والخروج، وAPI proxy المدعوم من Neon.
- البريد المؤكد مطلوب في الخادم قبل قبول هوية المستخدم أو تهيئة دور المالك أو الوصول إلى الشركات.
- لم ينشأ حساب مالك بكلمة مرور ثابتة، ولم ترسل رسائل تحقق آلية بواسطة أدوات العمل.
- تهيئة Neon Auth تمت على فرعي التطوير والتشغيل؛ لا توجد بيانات شركات تجريبية في قاعدة التشغيل.

الاختيار المقترح للاستضافة هو Netlify Free بعد استبعاد Render بطلب المستخدم. لا يوجد نشر Netlify مؤكد في هذه اللحظة؛ حساب Netlify يتطلب تسجيل دخول صاحب المشروع وربط المستودع.

نتائج البناء وفحوص HTTP ستضاف بعد اكتمال تنفيذها. نتائج اختبارات قواعد العمل الثمانية والثلاثين تخص المصدر المحفوظ دون تغيير في service.ts وpermissions.ts، وليست شهادة باختبار تسجيل الدخول الجديد من طرف إلى طرف.

## نتيجة التحقق من نسخة الاستضافة

- فحص TypeScript: ناجح.
- بناء Next.js production بواسطة webpack: ناجح، ويشمل API والهوية والدخول والدعوات.
- مقارنة SHA-256 لملفات service.ts وpermissions.ts وmigrations 001 و002 بالنسخة المختبرة: تطابق كامل.
- فحص HTTP المحلي والترويسات المزورة: لم ينفذ؛ رفضت أداة التنفيذ تشغيل خادم المعاينة بسبب قيود الأذونات، بما في ذلك محاولة إعداد محدود بمفتاح جلسة عشوائي مؤقت ودون قاعدة تشغيل.
- اختبار البريد/OTP والتسجيل والدخول واستعادة الجلسة من طرف إلى طرف: غير منفذ؛ يحتاج حسابًا وتجربة مستخدم فعلية بعد ربط الاستضافة.
- لم تنشأ خدمة Render أو تفعل خطة استضافة مدفوعة.

حالة النشر: المصدر مجهز لـNetlify Free. يلزم تسجيل دخول صاحب المشروع إلى Netlify وربط المستودع وإضافة أسرار البيئة والنطاق الموثوق في Neon. لا تعني نتيجة البناء وجود تطبيق منشور.
